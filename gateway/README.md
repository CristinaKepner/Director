# 体验网关

给别人发导演台的体验名额，而不发自己的密钥。

## 为什么不能在客户端做

客户端里没有任何位置能同时做到「限额」和「保住密钥」，这是结构上的，不是做得还不够好：

- **密钥藏不住。** dmg 里的后端是未压缩的源码（`Contents/Resources/app-src/`），而且就算藏起来，
  进程最后仍然要把 `authorization: Bearer …` 发到上游 —— 在自己的机器上抓一次包就有了。
- **计数删得掉。** 本机的额度记录只能落在一个文件里，删掉就重置，换台机器也一样。

所以密钥留在你的服务器上，客户端拿到的是一个**体验码**。额度在这一侧扣。

## 它是什么

一个零依赖的透明反向代理。导演台那边只改两个 base 地址，请求体一个字节不动 ——
上游换模型、加参数，网关都不用跟着改。它只做三件事：认体验码、换密钥、记账。

```
导演台 ──体验码──▶ 网关 ──真密钥──▶ AIGW（规划 / 读参照 / 验收）
                    │
                    └──真密钥──▶ 火山 Ark（出片）
```

两族路径：

| 客户端请求 | 转发到 | 计费 |
| --- | --- | --- |
| `/v1/*` | AIGW | 按上游报的 `usage.total_tokens` |
| `/ark/contents/generations/tasks`（POST）、`/ark/images/generations` | Ark | 每次 1 次出片 |
| `/ark/contents/generations/tasks/{id}`（GET / DELETE） | Ark | 不计费（查进度和取消不该收钱） |
| `/v1/quota` | — | 看自己还剩多少 |

## 起服务

```bash
node gateway/bin/gateway.mjs serve \
  --port 8787 \
  --llm-key-file ~/.aigw-key \
  --ark-key-file ~/.ark-key \
  --data ~/director-gateway/tokens.json \
  --url https://gw.example.com
```

前面挂一层 TLS（Caddy / Nginx / Cloudflare 都行）。网关自己不做 TLS，也不该直接朝公网监听 80/443。

## 发一个体验名额

```bash
node gateway/bin/gateway.mjs issue --label 张三 --tokens 100000 --calls 50 --days 7 \
  --url https://gw.example.com
```

打印出来的最后一行形如：

```
dt_9f0e…c802@https://gw.example.com
```

把这一行发给对方，他在导演台「偏好设置 → 体验码」里粘一次就能用。那一行里既有身份也有地址，
他不需要知道什么是网关，也拿不到任何密钥。

其它命令：

```bash
node gateway/bin/gateway.mjs list        # 每个码还剩多少、用了几次、什么时候到期
node gateway/bin/gateway.mjs revoke dt_… # 停用，最多 5 秒后生效，不用重启
node gateway/bin/gateway.mjs stats       # 总共发出去多少、已经花掉多少
```

发码和停用都可以在网关运行时做：服务端每 5 秒回读一次账本，遇到不认识的码也会立刻回读一次。
两边写同一个文件是安全的 —— 写之前先合并磁盘那份，`used` 只增不减取大值，`revoked` 一边说停就停。

## 额度怎么算

两条额度分开走，任一条触顶就拒：

- **token**：规划、读参照、验收这三条链，按上游返回的 `usage.total_tokens` 记。上游没报（部分流式响应）
  就按请求和响应的字符数估算，宁可高估。
- **次**：出片。视频和图按次计费更贴近真实成本，按 token 算不准。

扣减分两步：发给上游之前先悲观占住，回来之后按真实用量补平。所以十个请求同时进来，
不会十个都看到「还有余额」。请求没到上游（网络断了、上游 502）不扣额度。

同一个码最多同时压 4 个请求 —— 码一定会被转发给别人，这是第一道闸。

## 账本

一个 JSON 文件，原子写（临时文件 + rename），所以进程被杀不会写出半截。
到几万条再考虑换数据库；这个量级不值得让部署的人先装东西。

**这个文件等于钱**，权限 600，别放进会被同步的目录。

## 剩下没做的

- 没有管理 HTTP 接口，管理只能在服务器上用 CLI 做（这也意味着少一个能被攻击的面）。
- 没有按 IP 限速。一个码被挂到公开的地方会被刷满额度然后停住 —— 上限之内的损失，
  但拦不住浪费。真要发很多码时值得加。
- 不记录请求内容，只记条数和用量。要审计谁生成了什么，得另外接。
