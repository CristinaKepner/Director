# 行为测试与迁移保护

新增或修改业务逻辑必须同步交付充分的单元测试，相关外部协作另用集成或端到端测试验证。测试保护公开行为、数据契约和不变量，使内部实现可被替换；不能保证迁移完全无风险。

## 默认采用 TDD：红—绿—重构

这里的 TDD 指 Test-Driven Development（测试驱动开发）。新增或修改业务行为、修复缺陷时按以下顺序执行，不以事后补测试代替：

1. **明确行为**：从需求及业务文档选择一个足够小、可观察的行为或边界，确定输入、预期结果和不应发生的副作用。
2. **红**：先用 Vitest 写最小的行为测试，运行相关用例，确认因为目标能力缺失或缺陷而失败。核对断言及失败原因，测试环境、导入、语法或无关依赖故障不能算完成此阶段。
3. **绿**：实现满足当前用例的最小正确逻辑，优先复用已有能力或成熟库。重新运行相关测试，确保通过且未破坏直接受影响的既有行为；不硬编码样例、不弱化断言来过关。
4. **重构**：在测试通过的基础上改善职责、命名、依赖和封装，保持相同公开行为；运行相关测试和必要类型/lint 检查，确认仍通过。
5. **补足行为**：对下一条规则、边界或失败路径重复循环。局部实现完成后运行受影响范围的完整检查，核对覆盖和文档，不能只停在第一个正常路径。

- 修复缺陷先增加可复现回归用例并观察失败，再修复。已有失败用例已经准确表达目标时可以复用，不为形式重复编写。
- 既有功能缺少保护时先补特征测试；当前正确行为的测试可能直接通过，这是建立基线，不声称完成了红阶段。要改变的行为另补表达新预期的失败用例。
- 纯重构先确认保护现有行为的测试通过，再调整实现，不故意破坏代码制造红阶段。迁移先用旧实现建立契约基线，再让新实现满足同一组用例。
- 全新模块必要时仅建立可导入的最小接口/骨架，使失败落到行为断言；不先完成业务逻辑，也不把模块不存在导致的导入错误当作足够的业务验证。
- 不临时篡改正确断言、删除测试、滥用 mock、skip/todo 或关闭检查来制造红—绿记录。变更契约必须有需求依据。
- 测试无法实际运行时先解决可解决的环境问题；仍受阻则报告命令、原因和缺口，不将预测结果说成已经失败或通过。
- 纯文档、低影响样式或配置整理不机械要求失败单元测试；若修改可执行行为或构建契约，则选择相应可执行验证。保留用户已确认的可读性、行数与类型约束。
- 最终报告用例对应的行为、实际红阶段原因、绿阶段和相关回归结果；无需为每次循环新增日志文件，也不在 AGENTS.md 堆积过程记录。

## Vitest 基线

- 单元与集成测试使用 Vitest；React 交互使用 React Testing Library 和适当 DOM 环境。
- 领域、存储及宿主适配器按需使用 Node 环境；组件使用 DOM 环境。共享业务测试不启动 React 或 Electron。
- 开发支持 watch，自动化使用 `vitest run`。测试接入正常入口；只在本次需要时调整 CI。
- 使用既有安装版本和配置；若历史框架不同，说明差异并明确本次范围，不顺带全量迁移。
- 纯函数测规则，适配器测外部契约，集成测试测协作；关键用户流程补少量端到端验证，不每层重复同样用例。
- Vite、类型检查和测试分别验证；DOM 模拟不能证明 Electron IPC、WebCodecs、播放和打包正确。

## 单元测试充分性

- 实现前从需求、业务文档和现有代码识别本次规则及输入等价类，形成紧凑的“规则 → 用例/预期结果”清单。小改动可直接体现在测试名称，大改动在业务文档中保留对应关系。
- 每条新增或修改的重要规则必须有直接行为断言，不能只验证“不抛错”“对象存在”或 mock 被调用。
- 按相关性覆盖：正常结果、空值/空集合、边界值及边界两侧、非法输入、依赖失败、合法/非法状态转换；不为不可能状态制造无业务意义的用例。
- 有权限、预算、缓存、幂等、重试、取消、超时、并发或异步过期结果时，分别验证允许与拒绝、成功与失败路径，以及不应发生的副作用。
- 对 reducer、DAG 规则、缓存键、预算、事件回放、数据迁移及 Zustand action 等核心逻辑重点检查分支和不变量。重复调用、不同顺序或恢复场景按业务需要覆盖。
- 修复缺陷提供能体现修复前后差异的回归用例；重构依靠行为用例保持稳定，不因换私有函数而重写全部断言。
- 表驱动用例覆盖多组输入，测试数据命名表达业务含义；复杂组合只在有实际价值时使用性质测试，不无依据穷举所有组合。
- 使用 Vitest 兼容的覆盖率工具查看本次相关源码的行、函数和尤其分支覆盖，确认未覆盖路径。不得通过排除核心文件、忽略分支或制造弱断言提高数字。
- 遵守仓库已有覆盖率门槛；没有门槛时不擅自编造统一百分比。关键规则和失败路径必须有验证，合理未覆盖项说明原因和风险。
- 测试数据与实例隔离，可重复运行；不依赖执行顺序、真实等待、生产账号或收费服务。时钟、随机数、网络及进程按边界控制，不能 mock 掉待测业务。
- 第三方库内部实现不重复测试；验证本项目使用它的输入映射、配置、错误处理与业务结果。宿主/浏览器真实机制仍需要相应环境的验证，不能用大量 mock 单元测试代替。
- 单个测试只验证一个连贯行为，可以包含多条相关断言。测试函数同样遵守最多 10 行，通过清晰 fixture、命名助手及表驱动组织，不能压行或隐藏断言来凑数。

## 用例选择

- 功能：正常路径及相关边界、失败路径。
- 缺陷：优先先增加复现用例，确认修复前失败、修复后通过；已有正确用例足以覆盖时不机械新增。
- 重构/迁移：先保护行为再改实现。旧代码缺测试时补本次相关特征测试，不要求补齐全仓库。
- 区分应保持契约和已知缺陷，不将缺陷固化为正确结果。
- 低影响样式、文案及简单转发可复用已有验证，不强制增加测试文件。

## 可迁移的测试设计

- 从稳定业务入口调用，断言返回结果、持久化状态和可观察副作用，不绑定私有函数、目录或组件内部结构。
- 只在调用次数/顺序属于契约时断言，例如不重复扣费；不限制无关实现细节。
- 替身放在网络、时钟、随机数、外部进程等边界，不 mock 掉正在验证的核心。必要集成测试运行真实适配器。
- 固定时间/种子、隔离数据库与临时文件，清理测试资源；不依赖真实账号、付费请求或不稳定公共服务。
- 不同适配器共享契约用例，分别测试各自特有行为。
- 快照仅用于稳定、可审阅输出；不通过批量更新快照掩盖差异。
- 覆盖率只作辅助，不以数字替代关键风险分析。
- 若关键分支未验证或测试仍失败，继续补齐当前范围内的用例并修复；确有环境或信息阻碍则明确报告缺口，不能标为“充分通过”。

## 具体用例示例

按涉及模块选择，不是每次都运行全表，也不是已有测试实现的宣称。

| 模块 | 输入/场景 | 必须验证的结果 |
| --- | --- | --- |
| 事件状态 | 同一检查点和有序事件回放两次 | 领域结果一致；付费、文件和媒体副作用调用均为零 |
| 兼容 | 载入保留的旧版项目、事件与检查点 | 关键语义保留；未知未来版本明确拒绝且不覆盖原数据 |
| DAG | 循环、缺失输入、上游失败 | 执行前识别结构问题；失败传播符合规则，不伪造成功 |
| 缓存 | 同输入；再改变实现版本或资源版本 | 首次执行后可复用；相关变化使缓存失效，失败/取消不进成功缓存 |
| 预算 | 剩余额度不足；付费节点重试 | 执行前守卫生效；重试不绕过预算，不误算重复结果 |
| 操作入口 | UI 与 MCP 对相同操作提供合法输入 | 领域结果一致；不同入口权限分别验证 |
| IPC | 非法参数、超时、断连、宿主退出 | 错误明确；等待请求结束或进入可定位状态，不自动重放写操作 |
| 生命周期 | 多次打开/关闭项目，期间启动再取消任务 | 监听不累积；资源释放；旧任务不更新新项目 |
| 存储 | 事务中途失败，多窗口访问同一项目 | 原子性与既定并发规则保持，不出现部分提交或冲突副本 |
| 界面 | 双击提交、校验失败、关闭弹窗 | 不重复业务操作；错误可见；焦点恢复符合产品约定 |
| Effect | 依赖变化、卸载、Strict Mode 重复建立与清理、旧请求延迟返回 | 旧订阅释放且无累积；新依赖生效；过期结果不更新当前状态；无隐藏重复业务副作用 |
| 样式集成 | Tailwind 生产构建、主题切换和 Semi / React Flow 关键页面 | 条件类名生成完整；主题一致；Preflight 与层级未破坏组件表现；视觉结论来自实际界面验证 |
| Zustand | 执行 action、重置或切换项目，并延迟返回旧请求 | 状态和派生结果正确；实例与测试隔离；旧结果不污染新项目；不重复持久化副作用 |
| 媒体 | 固定小素材处理、失败或取消 | 检查实际产物及合理时长误差；源文件保留；进程与资源回收 |

## 架构与数据迁移

- 先读取[业务逻辑文档](business-logic.md)中的沉淀规则，在目标项目中查阅对应业务说明，提取需要保护的行为与已知差异；业务契约变化时同步文档、样本和测试。
- 列明必须保持的行为、持久化格式和允许变化，先建立基线。
- 业务用例可脱离 UI 执行；第三方运行时对象不进入长期数据格式。
- `import.meta.env` 等环境访问集中在配置入口，校验后注入；核心逻辑不依赖 Vite 插件、工作目录或开发服务器。
- 持久化资源不只依靠机器绝对路径；按产品需要使用资源 ID、项目相对路径或可重新定位引用。
- 长期数据有格式版本，迁移采用可测试转换；升级失败不以空项目兜底，不覆盖原数据。
- 说明备份、中断恢复及支持的回退方式。只有需求要求且实现支持时承诺回滚，不假定迁移天然可逆。
- 需要独立发布或版本共存时才增加协议协商，不提前建立版本框架。
- 适合时对相同输入比较新旧实现，明确时间、随机标识和浮点误差规则；只在纯计算或隔离环境双跑，不对真实写入、付费和发送双重调用。
- 按模块或用例逐步替换，避免同时捆绑界面重写、数据迁移和业务规则变化；完成后移除不再需要的兼容层。
- 跨语言迁移通常需重写实现；优先保全数据格式、契约、测试样本与行为规范。

## 验证与可复现交付

- package.json 中的直接注册表依赖使用精确版本并提交一致的锁文件；验证新依赖未被默认写入范围前缀，CI 按实际包管理器冻结锁文件安装。声明运行时和包管理器版本，统一开发、测试、类型检查及构建入口。
- 声明配置项与必要示例，不依赖个人机器隐藏设置；记录原生依赖和构建补丁的原因、限制与移除条件。
- 对 Electron 相关变更验证实际 preload、sandbox、IPC、窗口关闭和应用退出。涉及打包时验证原生模块、ffmpeg、资源路径及脱离 Vite 开发服务器的启动。
- 本地行为测试、类型检查、真实 Electron、打包产物和远端 CI 分别报告。未运行项明确原因；存在相关失败不得称验证通过。
