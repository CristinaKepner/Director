# VS Code 架构、Electron 与代码封装

适用：重要公共模块、服务边界、Electron 进程、IPC 与生命周期。以下为本项目对 VS Code 思想的取舍，不是其原架构的复刻。

## 参考方法

VS Code 是首要参考；当具体问题另有更贴近的成熟实现时，可以补充官方源码。先理解当前调用场景，再阅读对应接口、实现、消费者和测试。判断接口清晰度、类型质量、维护状态和兼容方式，不凭 Star 数量评价。

重要决策记录实际参考的源码路径、版本或提交，说明采用了什么、为什么；不要把链接到 main 的内容声称为固定版本。普通局部修改无需设计报告。

优先复用现有依赖；存在成熟且适配的第三方库时优先直接使用，不因参考 VS Code 源码就重新实现同类通用能力。自建产品核心时只吸收相关设计，不复制整套目录、插件机制、复杂泛型、继承体系或 DI 框架。开源库面向未知消费者的要求不能自动变成本应用需求。复制或改编源码前核查许可证并保留必要声明。

## 分层与环境

| 边界 | 职责 |
| --- | --- |
| 基础能力 | 稳定、跨业务的基础工具，不含产品流程 |
| 平台能力 | 文件、日志、存储、宿主通信的契约与实现，不依赖具体功能 |
| 领域与应用 | 事件、检查点、DAG 和业务用例，不依赖界面及具体宿主 |
| 工作台 | 布局、面板、功能入口，不维护具体领域规则 |
| 功能模块 | 画布、媒体、预演等业务能力，组件、逻辑、测试就近维护 |
| 装配入口 | 选择实现、注入依赖、注册功能并启动应用 |

这是逻辑边界，不要求立即建立对应目录或独立包。领域所需的端口由其稳定契约表达，不反向依赖平台实现。

- `common` 不使用 DOM、Node 或 Electron 专属 API；`browser` 可使用 Web API；`node` 可使用 Node API；`electron-*` 封装 Electron 专属集成。
- 通用代码不反向依赖专用环境代码；浏览器代码不直接导入 Node / Electron。共享业务可依赖无运行时耦合的校验库，不必只使用标准库。
- 同时用目录、tsconfig 及 lint 的禁止导入规则维护边界。模块只有实际存在多种环境实现时才创建对应子目录。
- 不通过统一导出文件混合浏览器与宿主实现，避免前端包引入原生依赖。
- 功能提供少量公开入口，不能跨模块深层导入。专用服务留在功能内部，多功能流程由明确协调者组织。
- 工作台通过显式装配接入功能；不采用导入即注册的隐藏行为。只为实际多个接入点增加小型注册机制。

## 服务与封装

- 接口围绕实际业务能力，避免万能 AppService / Manager / platform 对象。
- 函数参数或构造参数注入小依赖，具体实例在应用或功能入口连接；不在业务中随处查找全局容器。
- 服务明确属于应用、窗口、项目或任务，不默认全部为全局单例。
- 内部可变状态私有，对外提供明确方法、只读数据及必要事件。事件描述业务事实，不暴露内部字段变化作为长期契约。
- 操作请求执行并获取结果，事件通知已发生的变化。需要执行确认的流程不通过广播猜测完成。
- UI、快捷键、智能体和 MCP 复用业务用例，入口权限可以不同；不把本地快捷键包装或 IPC 方法当作领域协议。
- 不因为 VS Code 使用装饰器、类或全局注册，就放宽本项目显式依赖与严格类型要求。
- 借鉴类的职责和契约，不照搬继承树；优先组合独立能力。框架强制继承时仅保留薄适配子类，不建设万能基类或多层 protected 钩子流程；完整约束见主文件“避免复杂继承与隐式行为”。

## Electron 进程分工

| 执行位置 | 当前项目职责 |
| --- | --- |
| 主进程 | 应用生命周期、窗口、系统集成、进程协调 |
| 渲染进程 | React / Semi 界面、交互、浏览器侧媒体与 three.js 预演 |
| preload | 最小宿主桥接，不承载业务流程 |
| Worker / utility process | 按负载安排阻塞计算、存储或需要故障隔离的后台服务 |
| 外部子进程 | ffmpeg 等工具，由宿主服务管理启动、进度、取消和退出 |

- 以阻塞风险、故障隔离和共享需要决定进程拆分；不复制 VS Code 全部进程，不为每个功能创建进程。
- better-sqlite3 同步调用必须有明确存储执行边界，根据负载安排 Worker 或进程，不直接放入渲染层。数据库连接及写入规则有明确所有者。
- 异步网络调用不因“异步”就需要独立进程；也不能把 CPU 重计算包进 Promise 后声称不会阻塞。
- 主进程、界面保持响应；大型媒体计算不要在其中同步执行。

## 隔离与 IPC

- 显式启用 `contextIsolation` 和渲染进程 `sandbox`，关闭 `nodeIntegration`；preload 的实现遵守沙箱环境限制。
- 通过 `contextBridge` 暴露有限的业务能力，不暴露原始 `ipcRenderer`、任意通道调用、任意文件访问或命令执行。
- 宿主验证发送方、参数及资源范围，权限不只依赖按钮隐藏。回调只传业务数据，不把 Electron 事件对象交给页面。
- 分开业务契约、客户端适配、宿主处理和业务实现；普通业务代码不拼接通道字符串。
- 借鉴 channel/client/service 分离，但默认使用满足当前需要的简单通信，不提前实现通用 RPC、动态代理或自定义序列化协议。
- 请求/响应、事件、错误使用明确传输结构；外部边界运行时校验，静态类型不代表消息可信。
- 不跨进程直接传递类实例、DOM 或本地资源对象。大型媒体用文件、流或可转移数据，避免反复复制完整内容。
- 按实际需求定义请求 ID、取消、超时、订阅释放和断连处理。超时不代表执行停止；重连不能自动重放有副作用操作。
- 错误保留可判断的业务类别和必要诊断信息，不依赖 Error 实例跨进程保持原型。

## 生命周期与恢复

- 服务启动依赖显式表达；非首屏必需服务按需初始化，不依赖导入顺序启动。
- 借鉴 Disposable / DisposableStore 的所有权与集中清理思想，不强制继承公共基类；订阅返回可释放句柄，释放可安全重复调用。
- 资源创建者负责释放，转移所有权要明确。React 组件只清理自己拥有的资源，不销毁跨窗口或跨组件共享服务。
- 进程内按需使用 AbortSignal 等机制；跨进程转译取消请求，不直接传进程本地信号。区分取消请求、取消完成与资源释放完成。
- 异步清理需被等待时使用明确的异步关闭契约，不能塞进同步 dispose 后假设已完成。
- 关闭时停止接收新任务，根据产品语义取消或等待现有任务，完成必要持久化并回收所属进程；设置有界等待并明确超时后的数据处理。
- 窗口关闭后任务是取消还是后台继续，由产品规则决定，不靠进程是否存活隐式决定。
- 进程崩溃时终结或标记待处理请求，反馈状态；只重试有恢复语义的任务，不重复扣费、写入和媒体生成。
