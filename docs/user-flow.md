# 用户到导演台的动线

> 状态：2026-09-17。客户端 0.6.1，运行时 118 个 Action。
> 带「实测」的都是这台机器的日志和真跑出来的数，不是设想。
> 配套：UX 重构稿（图标版）https://claude.ai/artifact/JyYQY6tsc4bF2zWe7BudhQ

动线指的是**一个人从想做片子，到手里拿到一条片子，中间必须经过的每一步**——包括他在哪儿停下来、在哪儿等、在哪儿掉头。

这份文档不描述功能（功能清单在另一篇），只描述**顺序、等待和岔路**。

---

## 一、进来之前：他手里有什么

目标用户是想做片子但不是科班出身的人。动线的第一个判断就在这里：

| 他手里有 | 走哪条 | 占比预期 |
|---|---|---|
| 刷到的一条片子（链接） | 贴链接 | 主路径 |
| 一张截图 / 一段素材 | 拖文件 | 主路径 |
| 什么都没有，只有一个想法 | 说一句话 | 折叠，排第三 |

**为什么「说一句话」排第三**：空白输入框是创作者的敌人。而一张画面里恰好编码了最难用嘴说的东西——景别、机位高度、焦段、光位、构图关系。用嘴说这些要专业词汇，用图给只要拖一下。

所以首屏只问一件事：**想复刻哪条片子？**

## 二、第一次进来的八分钟

逐步记时长。**等待是动线的一部分**，不能假装它不存在。

| # | 他做什么 | 他看到什么 | 等多久 | 谁在干活 |
|---|---|---|---|---|
| 1 | 贴一条链接，回车 | 进度：连接 → 下载 | 3–20 s | yt-dlp，只下指定的那一段 |
| 2 | —— | 进度：读整条，分场景 | **20–60 s** | 多模态模型按时长抽 6–24 帧，切成最多 9 段 |
| 3 | —— | 场景、机位、灯、镜头一次建好；几个场景就分几块台（1/3/6/9 宫格） | < 1 s | 参照编译器（不过模型），批量 dispatch，算一个撤销步 |
| 4 | —— | 对话里多一条：「按整条建好了。只想要它的某一面？」四个选项挂在旁边 | 0 | 不拦路：不选就直接往下走 |
| 5 | （可选）换成「只要运镜」 | 同一份分析重编译，场重建 | **几毫秒** | 参照已缓存，不再读片 |
| 6 | —— | 自动跑一遍检查 | 几毫秒 | film.check |
| 7 | 点「录」 | 画面出现红框，时间码走 | = 镜头时长 | 浏览器抓帧 |
| 8 | 点「对照」 | 原片 ↔ 草片并排 | 0 | —— |

**到这里为止一分钱没花。** 这是整条动线最关键的性质：他在第 8 步已经能判断「机位走位对不对」，而还没进入任何计费环节。

第 4 步是这条动线最近一次大改（0.5.9）。以前这一步是把分析压成一段话交给 LLM 重新推导，要 115–195 秒，而且同一份分析两次建出不同的场。现在是编译，几毫秒，结果逐字节可重放。

## 三、主循环：改一镜

真正花时间的不是第一次建场，是这个循环。

```
       ┌─────────────────────────────────────────┐
       │                                         │
   改机位 / 改走位 / 改光  ──►  重录草片  ──►  对照
       ▲                                         │
       │                                    对上了？
       │                                    │      │
       └──────── 没对上 ────────────────────┘      ▼
                                              交给模型生成
                                                   │
                                                   ▼
                                            和草片再对一次
                                                   │
                                            ┌──────┴──────┐
                                          满意           不满意
                                            │               │
                                          锁住        只重做这一镜
```

三条规矩写在动线里：

1. **改完必须重录草片，再编译提示词，最后才生成**——顺序是有讲究的。不重录的话，对照左边是旧构图、右边按新构图出，那种对照是骗人的。
2. **重做的粒度是一镜**。不是整条片子重来，也不是一个参数重来。
3. **锁住的镜头，任何人都动不了**——包括 Agent。想改先解锁，解锁是显式动作。

## 四、不再停下来的地方

0.6.2 之前，整条动线上有一处**必须等人回答**：读完参照之后、建场之前问「你想复刻它的哪一部分？」。理由听着成立——建完场再改意图，前面的 Action 白跑。实际发生的是：导演贴完链接，屏幕停在「等你说要复刻哪一部分」，下一步录白模报 NO_SHOTS，一个镜头都没有。问得再具体也是在链路中间设了一道闸。

现在**默认整条复刻**，读完直接建。参照读完就存在工程里，换成「只要运镜」是一次免费的重编译（几毫秒，不再读片），所以选项摆在建好之后的对话里，不拦在建场之前。

**场次是一等公民。** 舞台顶上一条场次条：一块台一格，写着这一场有谁、几个人、几件道具、几镜多长、定妆了几个。点哪一场，舞台只画那一块（每个场景单独渲染），场景大纲、角色库、自检和 Agent 上下文都只看那一块——「机位低一点」只改这一场的。「全部」回到整台。

**时间线是剪辑本身**，不再折在「更多」里，放在流水线最前面（时间线 → 检查 → 草片 → 生成 → 成片）。里面有整条的标尺、原片切镜轨（读参照时切出来的段，按原片时间摆，点一段跳到对应的镜头）、Sequence 轨（拖动换序、拖右边缘改时长、切开、删除）、素材轨（定妆照 / Take / 首帧拖到任何一段上）。

**整条视频按场景分块。** 读取器先把片子切成最多 9 段（换了地方、换了人、或明显是另一个镜头），每段各自读景别 / 机位 / 光位 / 运镜；编译器把台面分成 1 / 3 / 6 / 9 宫格，一场一块、一块一个机位一个镜头。某一段读不出机位，就继承整条的读数，**不退到中性默认**——镜头选取降级过一次就等于没复刻。台上只挂一套预设灯（按第一场），别的场读出来的光记在那一镜上，生成时按它来。

四种模式还是四条岔路，各自的动线长度差别很大：

| 选的是 | 之后的动线 | 花多少 |
|---|---|---|
| 运镜照搬，主体换我的 | 建 7 步 → 录草片 → 对照 → 生成 | 只有生成计费 |
| 整条复刻 | 建 10 步（连场景和光）→ 同上 | 同上 |
| 只要打光和色调 | 建 5 步，机位给中性的 → 自己摆机位 | 同上 |
| 只要节奏 | 建 5 步，只有拍子 → 画面内容全自己来 | 同上 |
| （另一条）直接照原片生成 | 跳过草片，原片当参考视频直接出 | 快，但运镜是原片的，想改就得回到草片那条路 |

**选项自带下一步**：每个选项后面直接挂着要执行的 Action，不把答案丢回模型重推一遍。实测重推过两次，两次都推成 0 步——用户收到一句「会按原片照搬运镜」然后什么也没发生。

## 五、动线上的闸

有四道闸会拦住人。**闸不是 bug，是省钱和省时间的装置**——但每一道都必须说清为什么。

| 闸 | 什么时候拦 | 拦住的理由 | 怎么过 |
|---|---|---|---|
| 建场自检 | 录草片之前 | 这一镜的画面里没东西 / 拍的是墙 / 机位埋在实心代理体里 | 自动修，或人拿主意；确实要录可以显式越过 |
| 单条时长 | 提交生成时 | 这一镜比供应商单条上限长 | 先拆拍再逐段续拍。**刻意不自动转**——那会把一次点击变成四次计费 |
| 公网素材 | 提交 v2v 时 | 供应商要从公网抓草片，没有公网地址必然失败 | 开隧道 / 填自有地址 / 改用首帧参考 |
| 镜头锁 | 任何会动到已定镜头的操作 | 导演说过「这一块我满意了」 | 解锁，或带 force（会记进事件日志，事后查得到是谁） |

## 六、实测卡住的地方

这台机器的日志里能直接看到人卡在哪。**这几处是动线的真实断点，不是假设。**

| 卡点 | 日志证据 | 性质 | 状态 |
|---|---|---|---|
| **v2v 灰着，看起来像做不了** | 隧道 07:00:45 开始建，07:03:03 才好，中间换了三条 | 等待没有被表达。界面只说「需要公网地址」，和「这台机器做不了」长得一模一样 | **已修**：现在显示「正在建公网隧道 · 第 2 条…」 |
| **点「按景别放机位」只换来一句报错** | `camera.frame → TARGET_NOT_FOUND` 出现 3 次，都来自 human/console | 能力按存在暴露，不按状态暴露——按钮永远亮着 | **已修**：先拿这一镜点名的主体兜底，真没有才灰掉并说明 |
| **点一下镜头等将近一秒** | 大工程里 `shot.select` 254 ms、`camera.transform` 412 ms，加上广播接近 900 ms | 动线上每一步都被拖慢，累积起来是「这个软件很卡」 | **已修**：事件日志不再夹带 base64，降到 48 / 74 ms |
| **提交生成被拒，人不知道下一步** | `generation.submit → SHOT_TOO_LONG` | 闸说了「不行」，没说「走哪条路」 | **已修**：当场给出要分几段和先做什么 |
| **进了对照回不去** | 对照层盖住了视图三档，只剩「退出对照」 | 动线单向了 | **已修**：三档是常驻控件 |

## 七、新稿改了动线的哪几处

图标版的三块画板，改的都是动线而不是外观：

1. **首屏只问一件事。** 三张卡片、一行标题，73 个字。下面一排四个图标告诉他接下来会发生什么（草片 → 对一对 → 生成 → 成片），停上去才出现解释。
2. **底部十一个平铺 tab 收成一条有闸的路。** 以前「检查 / 生成 / 成片」是三个平级 tab，看不出自检不过就录不了草片。现在先后关系和闸都画在路上。
3. **该看对照的时刻，对照自己亮。** 草片刚录完（REVIEW）正是要比一比的时候，不指望人想起来去点。
4. **术语全部退到气泡里。** Take → 草片，v2v → 生成，Program → 拍到的，景别 / 焦段 / 机位高度一个都不出现在界面上——它们只在鼠标停上去那句话里，而且换成「站在哪、用多长的镜头、离地多高」。

## 八、动线上还没接上的几段

按挡路程度排。

| # | 断在哪 | 现在会发生什么 | 要补什么 |
|---|---|---|---|
| 1 | **车内戏、室内戏走不通** | 语义代理体是实心盒子，机位在盒子里，拍到的是内壁。检查查得出，修不了 | 让代理体支持「可进入」（空心 / 开口） |
| 2 | **改了机位，草片过期没人提醒** | 对照左边还是旧构图，人不知道该重录 | 记录机位版本，与录制时的版本比 |
| 3 | **不知道「现在为什么不能做」** | 按钮灰着，没有理由 | 给状态规则配一句人话，界面和 `/api/capabilities` 共用 |
| 4 | **四段进度是分开算的** | 看不到「66 镜里建好 / 录好 / 生成好各多少」 | 一个统一的聚合接口 |
| 5 | **有口播的片子做不了** | 资产库的「声音」一栏是空的 | 两个网关都没有 TTS 端点，要换供应商；还缺字幕对齐和本地字幕渲染 |

前四条都在动线内部；第 5 条是另一条动线（口播类爆款视频），现在完全没接。

## 九、最好的那条动线

前八节写的是**现在的**动线和它断在哪。这一节写它**应该是什么样**——一条从进来到拿到第一镜、中间没有一步是多余的路。

### 三条原则

1. **花钱之前，必须先看过不花钱的那一版。** 草片和原片并排对上了，才轮到模型。这是整个产品的立场，动线必须把它变成默认，而不是靠人自觉。
2. **能替他做的，就别让他点。** 每一步都问一句：这一步之后他*必然*要做什么？必然的事就自动做掉。
3. **Agent 只在三种时刻说话**：要你拿主意、做完了、出问题了。其余时候它闭嘴干活。

### 从进来到第一镜：九步，其中只有四步要人动手

1. **进来** —— 首屏只问一件事：「想复刻哪条片子？」不用动手。
2. **贴链接，回车。** ← 第 1 次动手。等约 25 秒（下载 + 读画面），屏幕上两步进度，写着在干什么。
3. **不用选。** 默认整条复刻，几个场景就分几块台。建好之后对话里挂着「只要运镜 / 只要光 / 只要节奏」，想换再点，换是免费的。
4. **建场 → 检查 → 录草片。** 不用动手，几秒钟。建完场之后他必然要看草片，所以直接录。检查没过的当场自动修，修不了的才停下来问。
5. **自动进对照。** 不用动手。原片 | 草片并排、一起播。草片刚录完正是该比的时刻，不指望人想起来去点。
6. **改。** ← 第 3 次动手（可以重复很多次）。跟 Agent 说一句「机位低一点」，或者直接拖。**每改一次，这一镜的草片自动重录**，对照左边永远是最新的——不重录的对照是骗人的。
7. **「出这一镜」。** ← 第 4 次动手，也是**第一次花钱**。按钮上直接写着：约 2 分钟 · 计费。到这一步他已经看过对照，知道自己买的是什么。
8. **等约 2 分钟。** 不用动手。对照自动换成 草片 | 生成，下面直接给验收结论：要改的改了没有、锁住的漂了没有。
9. **满意就锁，不满意说一句。** 说一句 → 只重做这一镜；锁 → 谁都别再动它，包括 Agent。

**到第一次看见对照：2 次动手、约 40 秒。到第一次花钱：4 次动手，而且之前必然看过对照。**

### 和现在差在哪

同一段路，现在要 7 次动手才看得到对照，而且第 5 步和第 6 步全靠人自觉：

- 第 3 步：现在选完模式还要再点一次「照这份建场」——**多一次点击**
- 第 4 步：现在建完场要自己点「录」——**多一次点击**，而且新手不知道该点
- 第 5 步：现在要自己想起来点「对照」——**最该被看见的一屏，藏在一个要人主动去点的按钮后面**
- 第 6 步：现在改完机位，草片还是旧的，没人提醒——**对照在骗人，而人不知道**
- 第 7 步：现在按钮上不写钱和时间——**第一次计费是在不知情的情况下发生的**

这五处就是把「现在的动线」变成「最好的动线」要做的全部工作，按顺序做：

1. 选模式即确认（合并两步，纯界面改动）
2. 建完场自动录第一条草片（`runBlockout` 接在 `reference.replicate` 后面）
3. 进入 REVIEW 状态时自动切到对照（状态迁移带一个建议视图）
4. 草片过期标记 + 改完自动重录（记录机位 / 实体的版本，和录制时的比）
5. 计费按钮标价（镜头秒数 × 供应商单价，提交前就算得出来）

### 三条支线

- **手里是文件不是链接**：第 2 步换成拖进来，省掉下载那几秒，其余完全一样。
- **什么都没有**：第 2、3 步换成说一句话。这条路没有原片，第 5 步的对照只有草片一栏——所以它排第三：没有参照可比，花钱之前那道保险就少了一半。
- **不是第一镜，是第 N 镜**：从第 6 步进来。镜头条上点一镜 → 对照 → 改 → 出。全片层面只多两步：「按分镜生成」（并行）和「导出成片」（没生成的用草片顶上）。

### Agent 在这条动线里该怎么说话

同一段对话（三步修改 + 一次思考 + 一次反问 + 一个八步计划 + 三镜出片 + 两句回复），实测：

- **改之前**：808 字、49 行、线程高 2332 px——要滚三屏
- **改之后**：276 字、21 行、905 px——一屏看完

做法和界面那一轮一样：**信息不删，只是不一次全摆出来。**

- **一轮对话一张卡。** 连着执行的步骤收成「改了 3 处」，点开才是逐步清单。三十步的计划也只占一行。
- **坏消息不折叠。** 失败的那一步永远露在外面——折叠不能把出问题的地方藏起来。
- **反问只剩问题和选项。** 为什么问、每个选项意味着什么，停上去才出现。以前一张反问卡摆五段文字。
- **思考是一个小标签**（「想了 12s」）。规划中是一行，不再滚一屏推理过程。
- **连着出片收成一排缩略图**（「3 镜出来了」），不再是三段一模一样的长句。
- **不说两遍。**「改了 3 处」下面不再跟一句「完成 3/3 步。」；只有没做成的那半句才留。
- **按钮上写人话，整句在气泡里。**「录这一镜」发出去的是 `录制 shot_01`——规划器要的是整句，人要的是四个字。
