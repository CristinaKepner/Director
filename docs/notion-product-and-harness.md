## 第一部分 · 产品方案

### 1. 立场

**即使上游 Agent 更强，生成端是否正确执行了空间操作，仍然必须独立验证。**

这是整个产品的地基。视频生成模型对「镜头推近三分之一」「人站到左边三分之一线上」「主光从左后 45 度打」这类空间指令的执行，既不稳定也不可自证。指望把提示词写得更好来解决，等于把验证责任推给一个没有验证能力的环节。

所以导演台的做法是：**把空间操作拿到 3D 里先做掉，让生成模型只负责它真正擅长的那部分——质感**。机位、焦段、走位、光位、时长在白模里是确定的、可测量的、可重复的；生成结果对不对，拿白模当基准去比。

这条立场决定了产品的形状：不是一个更好的提示词工具，是一个**可验证的预演层**。

**补一条本版才认识到的：预演层自己也需要被独立验证。** 实测跑一条 10 分钟的片子时，
66 个镜头全部录完、报 `ok: true`、拼成 9.8 分钟成片，而画面里大部分是墙 ——
一半机位没对准任何东西，12 个车内镜头的机位埋在实心代理体里面。
白模「不花钱」，所以没人会盯着看，空画面就这么一路绿灯走到生成端。
所以「执行了没有必须能验证」这句话不只对生成端成立，对 3D 那层同样成立（见 §13.5）。

### 2. 用户和他们真正的难处

目标用户是想做片子但不是科班出身的人。他们的难处不是不会用工具，是：

- **说不出那句话。** 空白输入框对创作者是敌人。「描述一下你想要的片子」——真正卡住人的就是这一步。
- **但他们手里有参照。** 刷到的一条片子、一张图、一个想复刻的镜头。而一张画面里恰好编码了最难用语言表达的东西：景别、机位高度、焦段感、光位、色调、构图关系。用嘴说这些要专业词汇，用图给只要拖一下。
- **不知道为什么要 3D。** 小白 get 不到 3D 的意义，是因为他从没见过「同一个构图、同一个运动、换一次生成人还是同一个人」。说一百遍不如并排播一次。

### 3. 三个入口，按难度从低到高

| 入口 | 用户付出 | 实现 |
|---|---|---|
| **贴一条链接** | 一个 URL | `reference.replicate`：下载 → 读画面 → 反问 → 建场 |
| **拖一张图 / 一段视频** | 一次拖拽 | 同上，跳过下载 |
| **说一句话** | 一句话 | 折叠成第二选项，不是首选 |

首屏的主位置给「给我一个参照」，文字输入框折叠在 `<details>` 里。这个排序是刻意的。

### 4. 核心循环

```
参照（链接 / 图 / 视频）
   ↓ 读出景别·机位高度·焦段·光位·运镜·拍数
Agent 反问：「这条是 MCU 28mm static，主体是 X。你想复刻它的哪一部分？」
   ↓ 导演选（运镜照搬换主体 / 整条复刻 / 只要光 / 只要节奏）
3D 建场：语义实体 + 机位 + 灯 + 镜头 + 拍
   ↓
白模预演（不花钱，改多少次都行）
   ↓
┌─ 和原片并排对照 ──→ 机位走位对上了没有
│
├─ 走白模：改 → 重录 → 生成 → 验收 → 单镜重做
│  慢，但运镜是你的，改哪一镜只重做那一镜
│
└─ 直接照原片生成：原片当 reference_video 交给 Seedance
   快，计费，运镜是它的
```

**反问放在读完之后**，不是读之前。读完才问得出具体问题——「你想要什么样的片子」是废话，「这条是 ECU 50mm static、主体是 X，你要它的运镜还是它的光」才是一个人能回答的问题。这也是整条链里唯一该停下来的地方：建完场再改意图，前面那些 Action 就白跑了。

### 5. 对照那一屏

产品里最该被看见的一屏。左右分栏，同步播放：

- **没生成时**：原片 | 白模。这时候白模的唯一意义就是和原片比机位走位对上没有，不摆出来根本没法判断。
- **生成之后**：白模 | 生成（可加「上一版生成」第三栏，可加「原片」）。

下面直接给验收结论（要改的改了没有、锁住的有没有漂），旁边是「改完重生成这一镜」。

**这个按钮的顺序有讲究**：先重录白模，再编译提示词，最后才生成。导演刚在 3D 里改了机位，不重录的话左边还是旧构图、右边却按新构图出——那种对照是骗人的。

对照必须在主舞台，不能塞进底部抽屉。放抽屉里会被压缩裁剪，而看不出差别的对照等于没做对照。

### 6. 一致性控制

生成模型每次调用都是无记忆的，所以一致性必须由 harness 维护：

```
generation.reference {entityId}  → 出定妆照 / 产品图，落成 asset（未批准）
asset.approve {id}               → 导演拍板
generation.submit {shotId}       → 该镜出现的实体的已批准参考自动随提示词提交
```

**参考绑在实体上，不绑在镜头上。** 演员 A 的定妆照批准一次，之后 A 出现的每个镜头自动带上，导演不用记得。

资产库按用途分组：①声音 ②角色（face / body / wardrobe）③物品。角色卡把一个角色的身份字段、按用途分组的参考资产、以及它出现在哪些镜头收在一起（`context.character`）。

### 7. 分发形态

- **浏览器**：`web/` 静态前端 + `server/` 后端。
- **macOS 客户端**：Electron 壳，起同一个后端、装同一份 `web/`。桌面端**没有自己的业务逻辑**——菜单项全部落到 Action Registry。
- **CLI**：`server/bin/director.mjs`，从 registry 自动生成命令。
- 创作数据在 `~/Movies/导演台/`，应用状态在 `~/Library/Application Support/导演台/`。覆盖安装不碰前者。

### 7.5 长片：分镜和分段是两回事

10 分钟 ÷ 单条 30 秒上限 = 至少 20 次调用，绕不过去。所以长片的问题不是「让模型吐出 10 分钟」，
而是**那些调用之间连成什么依赖图** —— 依赖图就是可修改性本身。

| | 分镜 | 分段 |
|---|---|---|
| 谁决定的 | 导演 | 模型的 30 秒上限 |
| 边界是什么 | **剪辑点，有意义**（动接动、反打、插入） | **假的，必须看不见** |
| 对观众 | 应该被感知 | 绝不能被感知 |
| 依赖 | 天然独立，改一镜是 O(1) | 串行（尾帧续拍），内在如此 |

两条推论：

1. **不能把段边界变成剪辑点。** 那等于让模型的 token 上限决定影片的剪辑节奏 ——
   生成端的限制往上渗进创作层，方向反了。
2. **段不是用户的编辑单位。** 用户改的是**镜**；段只是渲染这一镜的实现细节。
   把「重跑第 3 段」做成 UI 概念，和把段边界变剪辑点是同一个错误。
   段只该在一个地方对用户可见：进度和失败恢复（`shot.chain` 的 `resume`）。

**而且串行代价被高估了**：分段只发生在一镜之内，级联上限是「这一镜的段数」（2–4），
不是全片段数。实测那条 10 分钟片子 66 个镜头，**只有 1 个需要分段**，其余 65 镜单条就出得来。

真正省事的地方不在分段，在**语义反查**：换一个资产，影响哪些镜头，场景图里直接就有
（哪些镜头引用了实体 E），不需要内容指纹。指纹给你一个 bool，依赖关系给你一个**理由** ——
100 镜的时候，「这 7 镜要重做，因为主角换了参考图」才是人能用的东西。

## 第二部分 · Agent Harness

### 8. 主从关系

**Agent 真正要做的，不是替你点一下生成模型，而是替你完成整个工作。建模工具、渲染工具、版本管理工具，都只是它随时可以调用、也随时可以替换的能力。Agent 是主，工具是从。**

这句话不是口号，它对代码有具体约束。以「复刻一条片子」为例，这件事要经手四样东西：下载器（yt-dlp）、视觉模型（读画面）、规划器（LLM）、3D 运行时（建场）。

**错误的做法**是让界面按顺序去点这四样：下载按钮 → 解析按钮 → 建场按钮。那是工具在主导流程——换个下载器、换个视觉模型，界面就得跟着改，Agent 也没法自己跑这条链。

**正确的做法**是四样都收在 `hooks` 后面，由**一个 Action** 表达顺序和依赖：

```
reference.replicate { url | ref, from, to, hint }
  ├─ hooks.fetcher    下载      （yt-dlp，可换）
  ├─ hooks.reference  读画面    （视觉模型，可换）
  ├─ hooks.planner    翻成 Action（LLM，可换）
  └─ Action Registry  建场      （运行时）
```

界面点按钮走它，Agent 说「复刻这条链接」走的也是它——本来就是同一件事。

**边界要诚实。** 白模必须在页面里录（录的是真的在出帧的 Program 画面，后端没有 recorder），所以这条链在建场之后就停下来，明说下一步要页面参与，不假装做完了。hook 缺席时降级但不崩，这是契约。

### 9. 分层

```
Shell      web/ · desktop/ · CLI · curl / 外部 Agent
              ↓ 只发 Action，只持有视图状态（选中、视口、播放头、Tab）
Host       server/src/host.mjs   权威运行时 · 自动保存 · SSE 广播 · 媒体存储 · 录制看门狗
              ↓ 同一个 registry
Runtime    core/                 Source of Truth · Action Registry · 状态机 · 事件日志 · 撤销栈
              ↓ hooks
Adapters   ark 生成 · llm 规划 · film 拼片 · judge 验收 · reference 读图 · fetch 下载 · viewport 录制
```

四条不可违反的边界：

| 边界 | 规则 | 为什么 |
|---|---|---|
| Shell → Runtime | 只能发 Action，不能改 store | 否则事件日志漏记，撤销就不可信 |
| Runtime → 环境 | core 不 import DOM、不 import `node:` | 同一份 core 要能在页面、后端、CLI、测试里跑 |
| Runtime → 能力 | 通过 hooks，不直接调 | 录制只有浏览器能做、ffmpeg 只有后端有 |
| Host → Shell | 后端推完整快照，不推增量 | 多客户端同屏时不需要做冲突合并 |

### 10. 唯一入口：Action Registry

**118 个 Action**，每个都是一份完整契约：

```js
register("camera.transform", {
  doc: "移动机位",                  // Agent 的工具说明，也是 /api/capabilities 的输出
  params: { id: "string", height: "number", … },
  required: ["id"],
  validate: (payload, state) => …,  // 引用完整性：id 存在吗、枚举合法吗
  undoable: true,                   // 进撤销栈
  handler: (payload, meta) => …,    // 唯一允许 store.patch 的地方
});
```

分布：`project` 18 · `shot` 12 · `context` 11 · `camera` 10 · `entity` 9 · `agent` 8 · `generation` 6 · `take` 6 · `light` 5 · `scene` 5 · `timeline` 5 · `film` 4 · `motion` 4 · `reference` 4 · `asset` 3 · `review` 3 · `storyboard` 3 · 其他 2

`dispatch(name, payload, meta)` 依次做：状态机许可 → 锁检查 → 幂等键去重 → 必填检查 → `validate` → `--dry-run` 短路 → 压撤销栈 → 执行 → 记事件（source / actorId / before / after / ms / ok / forced）。

**这条路径是同步的。** 慢操作一律是「建任务 → 立刻返回 id → 适配器异步推进 → 进度写回任务 → SSE 广播」。新加的慢能力必须是这个形状。

> 踩过的坑：`reference.fetch` 的 handler 一开始写成了 `async`。dispatch 是同步的，返回 Promise 会让事件日志记下一个 Promise。

### 11. 状态机是权限闸，不是装饰

`EDIT → BLOCKING → REHEARSAL → ARMED → RECORDING → REVIEW → GENERATING → APPROVED`

每个 Action 声明自己在哪些状态下合法。录制中不能删演员、不能改焦距——不是靠界面把按钮灰掉，而是 **dispatch 直接拒绝**。界面灰按钮只是同一事实的第二次表达。

这条对 Agent 尤其重要：Agent 不看界面，它只能撞到这堵墙。

### 12. hooks：能力在哪一层实现

运行时声明契约，宿主注入实现。**目前八个**：

| hook | 谁实现 | 契约 |
|---|---|---|
| `capture` | 浏览器 viewport | `() → dataURL`，抓一帧 Program 画面 |
| `recorder` | 浏览器 viewport | `start(take, shot)` / `stop(id)`，录白模代理视频 |
| `generation` | `adapters/ark.mjs` | `submit(job, update)`；不认识的 provider 落回模拟队列 |
| `film` | `server/src/film.mjs` | `assemble` / `frames` / `toMp4` / `lastFrame`，ffmpeg |
| `judge` | `adapters/judge.mjs` | 抽帧 + 多模态比对新旧两版，出验收结论 |
| `reference` | `adapters/reference.mjs` | 图 / 视频 → 结构化拍摄参数 + 一句可建场的 brief |
| `fetcher` | `server/src/fetch.mjs` | `probe` / `download`，链接 → 本地素材（yt-dlp） |
| `planner` | `server/src/host.mjs` | `build(brief)`，自然语言 → Action 计划并执行 |

**`planner` 是这次新加的，意义最大**：规划器从此也是一个可替换的能力，而不是只有界面能调的特例。编排型 Action（如 `reference.replicate`）通过它去建场，换掉 planner 那条链照样成立。

规则：**hook 缺席时产品降级但不报错**。没有 ark key → 模拟队列照样能演完整流程；没有 ffmpeg → 返回带安装建议的错误而不是崩；没有浏览器 → `take.record` 无头完成。

### 13. 反问协议：选项自带下一步

Agent 要反问时，**每个选项自带「选了它就执行这个」**：

```js
options: [
  { label: "运镜和构图照搬，主体换成我的",
    detail: "…",
    recommended: true,
    next: { action: "reference.replicate", payload: { ref, hint: "…" } } },
  …
]
```

原来的做法是把答案作为文本发回规划器，让它重新推一遍该干什么。**实测连着两次推成 0 步**——用户收到一句「会按原片照搬运镜和构图」然后什么也没发生。

提问的那一方本来就知道每个答案对应什么动作，没有理由再绕一圈让模型重新推导。规划器规则保留为兜底（用户打字而不是点按钮时走它）。

### 13.6 参照编译器：分析已经是数字了，别再让模型猜回来

§13 那个错误在参照这条链上还留着一份，只是位置更靠前。读取器输出的是结构化的：
`shotSize: "MCU"`、`focalMm: 50`、`heightMeters: 1.15`、`motion.type: "push-in"`、
`beats: [{seconds: 3}, {seconds: 4.5}]`。而 `referenceBrief()` 把这些数字压成一段中文散文
（「机位高度约 1.15 米，焦段约 50mm」），再交给 LLM 猜回 Action。

代价是实打实的：没有规划器整条链走不通；慢且计费（实测单场 115–195 秒）；同一份分析两次
建出不同的场，还出现过一步不建（`BUILD_SAID_NOTHING_DONE`）；24mm 写成「约 24mm」，
模型顺手给 35mm，没人会发现。

**`core/reference-plan.js` 把这一段换成编译**：分析 → Action 计划，纯函数，不碰 store、
不调模型。空间参数走编译，语言走模型。

| | 散文 → 规划器 | 编译器 |
|---|---|---|
| 要不要 LLM | 必须 | 不要（只有导演另外打了一句话时才上场） |
| 实测耗时 | 115–195 s | **24 s**（其中读参照 ~20 s，编译几毫秒） |
| 同一份分析跑两次 | 结果不同 | 逐字节相同 |
| 50mm | 「约 50mm」→ 模型给 35 | **50** |
| 出错时 | 「模型没听懂」 | 「第 6 步 camera.frame 被拒：TARGET_NOT_FOUND」 |

**复刻什么，是四个开关，不是四段提示词**（`REPLICATE_MODES`：运镜 / 整条 / 只要光 /
只要节奏）—— 反问选项直接带 `mode` 过来，和 §13 的 `next` 是同一套做法。

**翻不动的要说出来。** 读取器的词汇和运行时的枚举本来就对不齐，以前全是静默吞掉的：
`LS`（运行时叫 `WS`）、`truck-left`（运行时是 `truck` 带方向）、`tilt`（运行时压根没有）、
`dutch`（没有滚转轴）。现在能翻的翻，翻不动的记成 warning 摆给导演 —— 和 §13.5 的自检
是同一个姿态：**探测器不假装自己是摄影师**。

编译出来的 `steps` 是一份能打印、能 diff、能重放的中间产物，每一步都带一句 why，
参照面板里直接摆出来。实测一条真素材：9 步、7.7 s、2 拍，建完跑 `film.check`
**0 error 0 warn** —— 对照 §17.5 那条 LLM 建的 10 分钟片子（17 个 error）。

### 13.5 建场自检：录之前先算一遍画面里有没有东西

`film.check` 是本版最有价值的新能力，起因是一次失败（§1、§17.5）：
一条 10 分钟的片子 66 镜全部录完、报成功、拼成成片，画面里大部分是墙。

它逐镜算，**纯本地几何，不用模型、不花钱、几毫秒**：

| 判据 | 查什么 | 级别 |
|---|---|---|
| `EMPTY_FRAME` | 三个取样帧的视锥里没有任何主体（只有地板和墙也算空） | error |
| `TITLE_SUBJECT_OFF_FRAME` | **镜头标题点名的东西不在画面里** | error |
| `SUBJECT_OFF_FRAME` | 指定的 `targetIds` 在画外 | error |
| `CAMERA_INSIDE_PROXY` | 机位埋在实心代理体里 | error |
| `NO_TARGET` / `SUBJECT_TOO_SMALL` | 没说拍谁 / 景别与实际占幅对不上 | warn |
| `CAMERA_UNUSED` / `CAMERA_OVERUSED` | 机位建了没用 / 多镜共用同机位且运镜相同 | warn |
| `NEEDS_CHAIN` / `TOO_SHORT` | 镜长超过或短于供应商上下限 | info |

`runBlockout` 录之前先跑一遍，有 error 就拦住 —— 不会再让人录十分钟才发现拍的是墙。

**`TITLE_SUBJECT_OFF_FRAME` 是其中最值钱的一条**：它不需要导演事先标注任何东西，
光凭镜头自己的标题就能发现机位摆错了（「21｜第一站灯下」点名了抱花姑娘，而她不在画面里）。

**每条问题自带能直接执行的修法**（和反问选项自带 `next` 是同一套做法：提出问题的一方
本来就知道怎么修）。要人拿主意的（这一镜到底拍谁、长镜头怎么拆拍、这个代理体要不要内部）
标成 `needsInput`，不自动执行 —— 那是调度决定，不是 bug。

**自检是探测器，不是摄影师。** 自动修能把「机位对着空气」变成「机位对着标题里那个东西」，
再往上是构图和调度，交回给导演。实测自动修一轮从 25 个错误收敛到 5 个，剩下的 5 个
是真正的多主体冲突（一个镜头同时点到人、后视镜和车外的人，没有哪个自动构图能同时满足）。

### 14. 加一个能力的标准流程

1. 在 `core/actions.js` 注册 Action：`doc` / `params` / `required` / `validate` / `undoable` / 状态机。慢操作按「建任务 + 异步推进」写。
2. 要外部能力就加 hook，别在 core 里 import 环境。
3. 宿主注入实现（`server/src/host.mjs` 或 `web/js/viewport.js`）。
4. Shell 接一个入口——按钮或菜单项，落到同一个 Action。
5. `tests/` 加一条无 UI 验收；`npm test && npm run test:api` 必须绿。

不需要改的：CLI、`/api/capabilities`、Agent 工具清单、事件日志、撤销。**这是这套 harness 的复利。**

### 15. 设计原则：先清空，再按需补充

1. **能力按状态暴露，不按存在暴露。** `capabilities()` 的 `allowedIn` 让界面、CLI、Agent 用同一份事实决定「现在能做什么」。还没有镜头时「导出成片」是灰的，不是藏起来也不是能点了再报错。
2. **主路径三步，其余进「更多」。** 不是把能力砍掉，是把**发现路径**排序：必需 → 常用 → 高级。

对 Agent 同理：工具清单给全，但状态机决定此刻哪些真的能调。人和 Agent 面对的是同一套收敛规则。

### 15.5 图标优先：把说明从界面上搬走

0.6.0 把「主路径三步，其余进更多」这条原则推到了界面本身。

**底部十一个平铺 tab 收成四段流水线**：检查 → 草片 → 生成 → 成片。功能一个没少 ——
镜头清单、时间线、故事版、参照、资产、事件、状态七个面板收进「更多」。排的是**发现路径**，
不是砍能力，所以测试里专门有一条守着：十一个 `data-bottom` 一个都不能丢。

**界面上不写句子。** 标签最多四个字，说明退到停上去才出现的那句气泡里。术语也一并退掉：
Take → 草片，v2v → 生成，Program → 拍到的，自检 → 检查。景别 / 焦段 / 机位高度这些词
一个都不出现在界面上，只在气泡里，而且换成「站在哪、用多长的镜头、离地多高」。

**图标取自 Lucide（ISC）**，原始 24×24 路径内联成雪碧图 —— 不联网、能换色、放大不糊。
指错 symbol 是静默失败（画面上少一个图标，不报错），所以测试里也守着这条。

**气泡做成一个全局元素 + 事件委托**，不是每个控件裹一层：动态渲染出来的镜头条、流水线
一样能用，也不会被祖先的 `overflow:hidden` 裁掉 —— 设计稿那一版正是栽在这上面。

**镜头条改成缩略图**：优先故事版关键帧，其次 Take 缩略图，都没有就画个空框。标题、时长、
「草片录没录」退到气泡。扫一眼靠图，看细节才停上去。

## 第三部分 · 实测到的能力边界

这些都是跑出来的结论。

### 16. 供应商

| 事实 | 结论 |
|---|---|
| Seedance 2.5 单条 **4–30 秒** | 超过要 `shot.beats` 拆拍 + `shot.chain` 分段续拍 |
| Seedance 2.0 单条 **4–12 秒** | |
| **12 条并发提交被接受** | 逐镜生成可以并行 |
| **两个网关都没有 TTS 接口** | 声音资产目前无法自产 |
| `reference_video` **不收 WebM，只收 mp4** | 提交前必须转容器 |
| `reference_video` **必须是公网 URL**，不吃 data URL | 需要隧道或公网地址 |

### 17. 长视频：工作流套娃

单条 30 秒上限绕过的办法是分段续拍：`shot.beats` 按剧情节奏（不是按秒数平均）拆成若干拍 → `shot.chain` 逐段生成，每段用上一段的尾帧当首帧。

实测 90 秒一镜到底：**5 段里 4 个接缝看不出来，1 个软接缝可见**。尾帧带人脸时会触发内容审核，自动降级为 t2v 并标记 `seamSoft`。

### 17.5 一条真跑出来的 10 分钟片子

用 `gpt-6-astra` 规划、白模逐镜录制、ffmpeg 拼接。**分四场建**，不是一次建全片
（一个 10 分钟的计划在一次调用里太脆，而且长片本来就该按场建）。

| | |
|---|---|
| 成片 | **9 分 55 秒**（595 s 计划 / 586.6 s 实际），1920×1080 24fps |
| 镜头 | **66 个**，中位 8 s，最长 45 s，最短 4 s |
| 语义实体 | 37（character 7 · prop 21 · building 6 · vehicle 1 · environment 2） |
| 机位 / 灯 | 26 / 7 |
| astra 规划耗时 | 四场分别 184 / 195 / 123 / 115 秒 |
| **需要分段的镜头** | **1 个**（第 52 镜，45 秒，astra 自己拆成 5 拍：6+9+14+11+5） |

`595 - 586.6 = 8.4` 秒的差摊在 66 段上是每段 0.13 秒，concat 的整帧对齐，**不是静默截断**
（逐镜核对过，0 个镜头录短）。

**这条片子印证了 §7.5**：65/66 镜单条就出得来，根本不进分段层。

**也暴露了 §13.5 要解决的问题**：66 镜全部录完、报 `ok: true`，而画面里大部分是墙。
自检事后在这条片子上一跑：17 个 error、6 个 warning，其中 12 条是「机位埋在公交车里面」。

### 18. 这次修掉的真 bug（共性：静默）

| bug | 症状 | 根因 |
|---|---|---|
| **录像器录了整块画布** | v2v 参考视频是 2122×1622 带黑边的窗口截图，不是导演摆的构图 | 节目画面只是画布中间那块信箱区；关键帧走 `grabProgram()` 一直裁对，视频却没裁。改成另开一块按工程画幅比例的画布逐帧贴过去，实测 1280×720 满幅 |
| **`scene.create{clear}` 清空 `d.jobs`** | 复刻任务「凭空消失」，分不清成了还是废了 | 规划器建场习惯开一张白纸，而它正是被 `reference.replicate` 叫起来的——一刀切把正在跑的编排任务连同进度一起抹掉。改成：在跑的和不属于任何镜头的一律留着 |
| **`clear` 开关吞掉 payload** | 返回 `ok:true` 但内容被丢弃，时间线上一条运动轨迹都没有 | `entity.path` / `entity.walk` / `light.keyframe` / `scene.room` / `shot.beats` 五处同一类 bug。**真的毁过一次数据**（一条片子的 9 条轨道运动）。改成：只在没有内容时才 clear |
| **打包后 yt-dlp 找不到 ffmpeg** | 装了 ffmpeg 的机器上照样报「合流需要 ffmpeg」 | yt-dlp 在 PATH 里找 ffmpeg，而打包 app 继承的是 launchd 的 PATH，没有 `/opt/homebrew/bin`。加 `--ffmpeg-location` 显式传 |
| **超长镜头被悄悄截短** | 点「重生成这一镜」，一个 45 秒的镜头回来 30 秒，报 ok，拼片时那个槽里少 15 秒 | `generation.submit` 里一直是 `Math.min(seconds, maxSeconds)`，而全代码库没有任何一处问过「这一镜需不需要分段」。改成 validate 当场拒绝并说清走哪条路；调用方替用户走 `shot.chain`。**刻意不自动转分段** —— 那会把一次点击变成四次计费 |
| **规划器的长计划被整份丢掉** | astra 把 10 分钟全片规划出来了（18,482 字符），撞上 token 上限截断，`JSON.parse` 抛错，回落到规则规划器答「没听懂」 | 参照读取器早有 `closeJson()` 抢救，规划器里没有。补上，上限提到 32000。80 个已规划好的镜头不该因为尾巴不完整就全部作废 |
| **`camera.frame` 把机位摆到地上** | 拍方向盘的机位离地 0.15 米 —— 趴在地上拍 | 机位高度算的是 `h × 比例`，`h` 是主体**自身**高度。对人成立（1.7m → 齐眼），对 `dim=[0.46,0.08,0.46]` 的方向盘就是贴地。改成围绕主体在世界里的实际高度。**这是自检自动修来回震荡的真因**（14→16→11→16 变成 25→8→8→5 收敛） |
| **修一镜拆掉另外十四镜** | 自检一键修 39 条，错误反而从 23 涨到 25 | 修法直接调 `camera.frame`，而 15 个镜头共用一个机位。新增 `shot.reframe`：机位若被共用，先克隆一个专属的再摆 |
| **打包后的客户端开不出隧道** | 装了 cloudflared 的机器上，v2v 永远回 `NO_PUBLIC_MEDIA_URL` | 隧道只在 PATH 里找 cloudflared，而从访达启动的 app 继承的是 launchd 的 PATH（没有 `/opt/homebrew/bin`）。ffmpeg / yt-dlp 早就按固定位置探测，隧道这里一直没跟上。补上探测，并给后端进程补回常见安装目录 |
| **一条隧道没通就判 v2v 死刑** | cloudflared 报 Registered、也给了 `*.trycloudflare.com` 地址，那个主机名却始终不通 | quick tunnel 的随机故障（实测连开三条，前两条不通第三条通）。改成最多换三条；而且本机一次 HTTP 应答都没拿到时不判死 —— Clash 这类代理会掐断到 trycloudflare 的 TLS，而要能取到视频的是 Ark 的服务器，不是这台机器。这种情况标成「已建立但未验证」继续用，日志里说清楚 |
| **隧道失败留下孤儿进程** | 重启几次攒出一堆 cloudflared，见过跨天还活着的 | 失败路径只把 `tunnel` 置空，没有 `stop()` |
| **事件日志把工程撑到 48 MB** | 一条 10 分钟的片子，点一下镜头要等将近一秒 | 事件的 before/after 直接存了 base64 缩略图；日志又是状态的一部分，于是每个 Action 的深拷贝、每次自动保存、每条撤销快照都把它整份复制一遍。改成：日志里只留替身（`data:…base64,…(48 KB)`），深拷贝时把日志摘出去，撤销快照不带日志（`restoreSnapshot` 本来就保留当前那一份）。**实测同一个工程 254 → 48 ms/次** |
| **「按景别放机位」永远是亮的** | 机位没写「看向」时点它，只换来一句 `TARGET_NOT_FOUND` | 违反自己定的「能力按状态暴露，不按存在暴露」。改成先拿这一镜点名的主体兜底，真的一个都没有才灰掉并说清为什么 |
| **进了对照就找不到视图三档** | 「自由 / Program / 对照」那一组被对照层盖住，回去只剩「退出对照」一条路 | 对照层 z-index 5，HUD 没写 z-index。菜单里也没有对照这一档（`view` 命令把非 program 一律当 free）。HUD 提到 z-index 6、对照底部留出它的高度、菜单补上 Cmd+3 |
| **从对照切回自由/Program 再进对照是一片黑** | 对照那一屏永远空着，再也回不来 | `dataset.key` 是防重绘的缓存键。退出时清了 `innerHTML` 却留着 key，再进来 key 命中直接 return。顺带 Program 按钮在对照模式下也亮着（判断写的是 `!== "free"`，加第三档后就错了） |

**共性**：全都是「报成功但没做」或「静默丢东西」。这类 bug 比崩溃危险得多——崩溃会被发现，静默失败会被当成模型能力不行。这也反过来印证了第 1 节的立场：**执行了没有，必须能独立验证。**

**本版最重要的一条不在表里，因为它不是 bug 是限制**：语义代理体是**实心盒子，没有内部**。
车内戏、室内戏的机位在盒子里面，拍到的是盒子内壁 —— 一整面纯色。实测那条 10 分钟片子
12 个车内镜头全是这样，**这才是画面难看的真正原因**，比机位没对准严重得多。
而且光看「画面里有没有东西」查不出来：盒子内壁确实在画面里。`CAMERA_INSIDE_PROXY` 单独判它。

### 19. 已知失败模式与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `NO_PUBLIC_MEDIA_URL` / `V2V_NEEDS_PUBLIC_MEDIA` | v2v 参考视频必须公网可达 | `--tunnel cloudflared`（只读放开 `/media`）或 `--public-url`；否则用 i2v。**提交前就拒绝**，不排队等四十秒再失败 |
| `TUNNEL_UNREACHABLE` | 拿到 trycloudflare 地址但公网不通。两种成因：① quick tunnel 自己的随机故障；② 本机代理（Clash / Surge 的 fake-IP）掐断了到 trycloudflare / argotunnel 的连接 | 最多换三条隧道重试。全都验不过、而且本机一次 HTTP 应答都没拿到时，按「已建立但未验证」继续用 —— 本机连不上不等于 Ark 连不上（实测就是这样出的片）。想让本机也验得过：给 `198.41.192.0/24`、`198.41.200.0/24` 和 `+.trycloudflare.com` 加直连规则 |
| `InvalidParameter: Bad Request`（v2v，18% 处失败） | Ark 的 `reference_video` 不收 WebM。任务能创建成功，它事后抓取时才失败，报错却回落成参数错误 | `film.toMp4()` 提交前转容器。**A/B 验证：同隧道同内容，webm 失败、mp4 running** |
| `InputImageSensitiveContentDetected` | 续拍尾帧带人脸触发审核 | 自动降级 t2v，标 `seamSoft` |
| 网关 400 参数不支持 | 各厂商参数拼法不一（`max_completion_tokens`、固定 temperature、无 `json_object`） | 适配器按错误信息就地协商并记住该模型的写法，最多三次 |
| 客户端录制中途关窗 | Take 卡在 RECORDING | Host 录制看门狗收尾 |
| `SHOT_TOO_LONG` | 镜长超过供应商单条上限 | 当场拒绝并给出要分几段；先 `shot.beats` 拆拍再 `shot.chain`。不自动转，避免一次点击变四次计费 |
| `CHECK_FAILED` | 建场自检发现会拍空/拍错的镜头 | 录制被拦住，问题列表带修法；确实要录可 `runBlockout({check:false})` |
| 规划器「只说不做」 | 模型把建场请求当成汇报，回一句话、0 步 | brief 上来就是祈使句；反问选项自带 `next`；0 步时报 `BUILD_SAID_NOTHING_DONE` 并附上模型原话，而不是一个没头没脑的 `BUILD_EMPTY` |

### 20. 没做 / 待定

- **语义代理体没有内部。** 实心盒子，车内戏、室内戏拍不了（见 §18 结尾）。自检能查出来，
  但修不了 —— 要让代理体支持「可进入」（空心 / 开口）。**这是目前最挡路的一条**：
  一部大半发生在车厢里的片子，用实心盒子当车就永远拍不出来。
- **声音**：两个网关都没有 TTS 端点，资产库的「声音」一栏是空的。
- **资产替换的影响范围**（`asset.swap`）：语义反查的基础设施在（`context.character` 能说
  某实体出现在哪些镜头），但还没做成「一次返回影响 N 镜 + 预估代价 + 确认后执行」的动作。
- **改动影响范围在按钮上可见**：「改这一镜 → 1 镜 · 约 4 分钟」对比「改这一拍 → 后面 7 段作废」。
- **场级视觉锚点**：100 镜下单张人物参考图会漂，每场需要几张标准剧照当基准。
- **审片扫描**：judge 目前是单次验收，长片需要自动扫一遍出可疑清单。
- **签名与公证**：客户端未签名，对外分发会被 Gatekeeper 拦。静默自更新需要 Developer ID。
- **论文的度量层**：机位控制精度、非目标区域保持度的客观指标、失败分层标注 —— 设计了没落地。
- **`generation.submit` 的 `reference: "origin"`**（拿原片当参考视频）：提交路径验证过，
  未跑完整条出片。
