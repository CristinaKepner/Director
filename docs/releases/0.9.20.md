# 0.9.20：v2v 媒体准备与分发修复

视频生视频始终提交 `video_url / reference_video`，保留整段参考运动；不会自动降级为单张关键帧 i2v。

## 本版改变

- DMG 内置 Cloudflare 官方 cloudflared 2026.10.2，分别包含 arm64 / x64 二进制。构建脚本固定发布资产 SHA-256；许可证随包放在 `docs/licenses`。用户开启公网媒体开关后无需安装 Homebrew。
- 每次提交 v2v 前，先转码、检查参考片段，再对最终公网 MP4 进行无鉴权 Range 读取。HTTP 530、登录页、非 MP4、TLS/连接超时均在创建模型任务前停止；不把 Ark key 发给媒体域名。
- 已配置发布器时，公网直连失败后可改用该发布器，仍需验证返回的媒体地址。不自动选择第三方上传服务。
- 隧道必须取回完整且一致的探针才会就绪；“已注册但无法验证”不再作为成功。进程退出会撤销地址，并通知主页面。
- v2v 转成 H.264 / 30 fps / yuv420p / faststart MP4；短边 720 px，保留画幅。参考画幅须为 2:5–5:2，Seedance 2.5 参考片段须为 2–30 秒（2.0 为 2–15 秒），文件上限 200 MB。超限要求调整片段，不静默截短、循环或变形。来自原片时仍使用所选镜头的时间范围。
- 准备参考期间取消任务或切换工程后，不再继续创建远端任务。任务创建后发现取消，则请求撤销远端任务。
- 配乐混音改为按成片长度计算有限循环次数，避免随包 FFmpeg 的无限音源循环阻塞。

## 分发边界

本版 DMG 最低为 macOS 15：随包 cloudflared 官方二进制声明 `minos 15.0`。不通过修改 Mach-O 版本标记假装兼容旧系统；旧系统的兼容构建需另行验证。

**本版不是“只填 key 即可稳定 v2v”的托管方案。** Ark key 授权模型调用，并不自动给本地参考视频提供公网托管；还需要模型开通、额度，以及 Ark 可读取的参考视频地址。Cloudflare 临时隧道仍受用户网络、代理和防火墙影响。提交前的本机探测也不能证明 Ark 所在网络一定可达。

要实现面向所有用户的 key-only 流程，产品需提供有鉴权、容量限制和到期清理的媒体上传服务，返回模型可读取的短期下载地址；客户端仍须遵循用户对参考媒体传输的授权。本版未接入或假装存在该基础设施。

2026-10-21 无付费探测：方舟 Files API 的 `user_data` 和 `agent` 上传均成功，但响应未提供可用的 `download_url`，因此没有将它作为视频托管实现。合成测试文件均已删除。不能把用于视频理解的 `file_id` 当成视频生成支持的输入。

本机真实 Cloudflare 公网探测仍失败；没有完成真实模型出片验收。只允许在用户明确确认次数/时长预算之后进行真实生成。

FFmpeg 上游发布标签为 `b6.1.1`，实际二进制版本分别为 arm64 `6.0`、x64 `6.1.1-tessus`。构建缓存区分下载原始哈希与 ad-hoc 签名后哈希，避免签名后的缓存被反复重下。

## 验证与复现

- `npm run test:all`：278/278 通过，包含媒体错误拦截、取消、发布器回退、密钥隔离、转码尺寸/时长、隧道校验/退出和配乐混音。
- `npm run test:features`、`npm run build:web` 通过。
- 新增模块与测试使用现有 ESLint 的 10 行函数约束；历史装配函数未做全仓重构。
- 打包：`cd desktop && npm ci && npm run dist`。DMG 未配置 Developer ID 签名和 Apple 公证；不能等同于已完成正式公开发布审核。
