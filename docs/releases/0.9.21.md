# Director 0.9.21：参考图片与视频上传

主页面的「素材与参照」增加图片/视频批量上传、拖拽、进度、取消、手动重试、预览及尺寸/时长信息。参考来源可直接加入节点，或选择到复刻面板；导入不会自动批准身份参考或触发付费分析。

新增原始文件上传接口 `/api/reference-media`，使用现有 API 认证；流式暂存、文件签名与 FFmpeg 解码检查、上传大小限制、工程切换隔离、重复请求去重。视频保持完整原文件；不把 i2v 单帧当作 v2v。引导弹窗与节点导入复用该接口，旧音频/Take 上传不变。

完整契约与规则见 [素材功能文档](../features/assets/README.md)。交互参考 OpenFilm 的媒体池，仍使用 Director 的原生主页面、共享状态和 Action。

## 产品自有媒体服务的部署契约（设计，尚未部署）

要让最终用户只配置 Ark key，分发方需提供稳定的 HTTPS 上传服务与独立产品身份认证，而不是要求模型供应商去读用户本机。推荐契约：

1. `POST /v1/media/uploads`：产品登录凭据鉴权，提交 MIME、bytes、sha256，服务器按账户配额签发短期上传凭证和对象 ID。Ark key 不发送给媒体服务。
2. `PUT <uploadUrl>`：客户端流式传原文件；服务限制文件大小、校验内容/摘要，隔离存储，不公开执行内容。
3. `POST /v1/media/uploads/:id/complete`：服务完成校验后返回 `{mediaId, downloadUrl, expiresAt, mime, bytes}`。下载 URL 使用不可猜测签名、支持 Range 和正确 Content-Type，建议有效期覆盖任务排队与生成时间。
4. `DELETE /v1/media/:id`：取消或用户删除时撤销；定时清理过期对象。失败可按同一上传 ID 重试，不自动重提模型任务。
5. 桌面客户端在用户确认生成时发布必要媒体、验证视频实际字节可读，然后才提交一次 Ark 任务；任务轮询只查询同一 taskId。上传超时、签名过期与模型任务错误分别提示。

部署需要产品的服务域名、对象存储及认证方案；本轮没有这些环境信息，因此没有把一个未部署地址写进客户端，也没有借用无关第三方公共图床上传用户素材。
